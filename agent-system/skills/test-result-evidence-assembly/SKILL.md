# Отчёт тестирования

Собери `test-report.md` из плана и фактических свидетельств нужной версии. Для каждой проверки используй `passed`, `failed`, `blocked`, `not-run` или `not-applicable` с основанием. Не исключай обязательное из покрытия только потому, что проверка недоступна.

Включи: версию и область; окружение; покрытие нового поведения и соседних функций; таблицу результатов со ссылками на evidence; дефекты с условиями воспроизведения и последствиями; непроверенные части и их влияние; необходимые исправления и повторные проверки.

Если указаны численные итоги, они должны сходиться с реестром и явно включать знаменатель. Общая доля успешных тестов не заменяет проверки важного критерия. Результат автора, неподходящий тест или устаревший лог не выдавай за текущую независимую проверку.

Статусы пакета: `checks-completed` означает завершение назначенных проверок с указанными исходами, а не отсутствие дефектов; `incomplete` или `blocked` — неполный пакет. При обязательных failed/blocked/not-run не делай вывод «изменение работает полностью». Передай orchestrator версию, дефекты, ограничения и пакет для Review.
