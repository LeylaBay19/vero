# Пакет разработки изменений

Маршрут: analyst → specification → design → implementation → testing → независимый review → verification → человек; координатор — orchestrator. Это набор доступных этапов, не требование повторять уже актуальные результаты или запускать код по просьбе только о проектировании.

- Analyst устанавливает текущее состояние и влияние предоставленного требования; при наличии требования добавляет impact-map.md, при отсутствии отмечает неприменимость.
- Specification формализует разрешённое будущее поведение и проверяет контракт. Передача design требует готовой области и актуального анализа архитектуры.
- Design готовит способ реализации и план изменений/проверок без выполнения кода. Если поручен только дизайн, маршрут заканчивается соответствующими документами.
- Для Implementation нужны явная задача реализации и сообщённое пользователем согласование конкретного дизайна. Повторное разрешение обычных действий внутри уже порученной задачи не требуется. Новое продуктовое решение возвращается человеку.
- Testing проверяет фактическую версию, значимые границы и затронутую регрессию в разрешённой среде, фиксируя выполненное и недоступное. Авторская самопроверка не заменяет этот этап.
- Review назначается отдельному исполнителю, не автору реализации. Он изучает оригиналы, изменения и тестовые свидетельства.
- Исправление возвращается ответственной роли. Затронутые тесты, существенные замечания review и строки верификации обновляются для новой версии; старые результаты не становятся актуальными автоматически.
- Verification проверяет каждый исходный критерий по полной применимой цепочке. Неподтверждённая обязательная часть или незакрытый существенный дефект не позволяют общий положительный итог.

Человеческая приёмка отдельна от верификации. Deploy, публикация, merge, внешние сообщения и работа с production не следуют автоматически из этого маршрута. Общие правила и ограничения среды сохраняются.
