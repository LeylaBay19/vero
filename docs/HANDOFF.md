# Передача проекта

## Обновление 04.11.2026 · v1.2.0

По браузерным комментариям пользователя исправлена ветка существующей организации: сначала проверка сохранённой связи аккаунта с компанией. Подтверждённые подключения открывают кабинет с назначенными правами. Гендиректор без связи подтверждает полномочия УКЭП и проходит проверку, не создавая дубль компании; сотрудник без доступа обращается за приглашением. Повторный личный вход без УКЭП не отменяет ранее подтверждённую роль, приглашения и подготовку МЧД. Для подписи МЧД нужна УКЭП, без сертификата подпись не выполняется. В стенде сведения о прежнем доступе задаются переключателем тестовых данных; это не реальный выбор роли пользователем.

В BPMN роли вынесены в отдельную левую колонку. У возврата к подписи после ошибки удалён пяти-пиксельный излом. Предыдущий полный снимок v1.1.0 сохранён локальным Git-тегом. GitHub пока ожидает настройки входа Git пользователем; без проверки не утверждать, что версии отправлены.

## Обновление 04.11.2026 · v1.1.0

По явному поручению пользователя приглашение сотрудника заменено единым процессом:
любая личная/корпоративная почта → mos.ru без повторного ИНН → принятие → автоматическая МЧД руководителю при наличии выбранных полномочий. Полномочия выбираются при приглашении один раз. Совпадение почт не требуется. Обычный доступ активируется после принятия; полномочия МЧД — после подписи гендиректора и успешной проверки. Сотрудник свою МЧД не подписывает. В стенде добавлены переключение между участниками и результат проверки подписи; реальные интеграции и проверка личности не подключены. Контекст перехода хранится в памяти сеанса, перезагрузка сбрасывает демонстрацию.

Обновлены BPMN с дорожками «Сотрудник / Платформа / Генеральный директор», SVG/PNG, автономная страница схем и web/. Прежняя ветка email/пароль по приглашению отменена; флоу конкурентов сохранены. Проверены новый единый сценарий, необязательная МЧД, разные почты, отмена mos.ru, защита от обхода этапов, ошибка подписи и повтор, сохранение обычных прав, отсутствие административных прав от МЧД, sandbox и схемы. `npm test` пройден.

## Предыдущее состояние (архив контекста)

Состояние на 03.11.2026: интерактивный прототип с четырьмя верхними флоу — Тринити/mos.ru, Тринити/УКЭП, Орбита/email и предлагаемый вариант.

В предлагаемом варианте доступны три пути стенда: регистрация организации, регистрация сотрудника, полномочия сотрудника/МЧД. Для сотрудника есть приглашение, отсутствие приглашения и кейс организации на mos.ru. Отдельный самостоятельный запрос доступа полностью удалён.

Последнее поручение: руководитель отмечает полномочия чекбоксами, платформа формирует МЧД, руководитель подписывает её ЭП. Обычное подключение сотрудника через приглашение остаётся независимым. В прототипе есть защита от пропуска формирования и подписи, пустого выбора и сохранения статуса готовой МЧД после изменения чекбоксов. Сотрудник видит оформленные полномочия без получения административных прав.

Готовы четыре процесса в diagrams/: организация, приглашение сотрудника, организация на mos.ru, МЧД. Для каждого есть .bpmn с DI, .svg и .png. schemes.html включает все схемы и BPMN в одном файле. В web/processes.html размещена хостинговая версия.

В исходной рабочей среде пройдены проверки: генерация HTML; обе ветки приглашения; регистрация гендиректора; отсутствие запроса доступа; контактная заглушка; возврат/отмена mos.ru; отсутствие выдачи местных прав по внешнему членству; МЧД; sandbox/CSP; автономные схемы и точное содержимое вложенных BPMN; размеры 320/736/1100, светлая/тёмная тема; регрессия первых трёх конкурентных флоу.

Переносимая сборка scripts/build_all.py проверена на Windows. Все четыре перенесённые UI-проверки также пройдены. Тест sandbox ожидает стабилизацию высоты iframe перед быстрыми последовательными кликами. Для новой среды проверки запускаются по README. Форматы документов и серверные интеграции не реализованы; полный состав реквизитов МЧД, криптографическая подпись, срок, отзыв и реестр требуют отдельной спецификации.
