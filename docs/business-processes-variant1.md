# Вариант 1 — процессы регистрации и входа

Версия 1.24.0. Состояние: предлагаемый процесс, отражённый в HTML-прототипе. Владелец бизнес-процессов не установлен. Цели ниже восстановлены из поручения пользователя моделировать регистрацию/авторизацию; серверная реализация не подтверждена.

Источники: решения пользователя 05.11.2026; src/registration-mos-id.js (функции view/allowMos/openCabinet и обработчики); src/platform-entry.html (authOnly, certificate/application); ТЗ 1.0 §6.2/LK-06 только для сохранения проверки до административных прав.

## AUTH1_EMAIL — Регистрация по email

Цель: Создать подтверждённый личный аккаунт перед подключением организации.

Запуск: Начать регистрацию. Условия запуска: пользователь находится в соответствующем сценарии стенда; для подключения организации аккаунт уже создан, для привязки mos.ru — пользователь авторизован, для приглашения — открыта ссылка организации.

| ID | Участник | Действие / условие |
|---|---|---|
| start | Пользователь | Начать регистрацию |
| email | Пользователь | Указать email |
| mail | Платформа | Показать отправку письма |
| open | Пользователь | Открыть письмо и подтвердить email |
| valid_link | Платформа | Ссылка действительна? |
| expired | Пользователь | Запросить новое письмо |
| password | Пользователь | Задать пароль, повторить и принять условия |
| valid_form | Платформа | Данные и согласие верны? |
| fix | Пользователь | Исправить ввод; остальные данные сохранены |
| create | Платформа | Создать аккаунт; email становится логином |
| mos_offer | Пользователь | Подключить Mos ID или сделать позже |
| done | Пользователь | Аккаунт готов; далее подключение организации |

Ветви: start → email; email → mail; mail → open; open → valid_link; valid_link → password (Да); valid_link → expired (Нет); expired → mail (Новое письмо); password → valid_form; valid_form → create (Да); valid_form → fix (Нет); fix → password (Повторить); create → mos_offer; mos_offer → done.

Результаты: Аккаунт готов; далее подключение организации.

- Поле логина после подтверждения email заблокировано. Пароль задаётся пользователем, согласие не отмечается автоматически.
- Необязательная привязка Mos ID раскрыта в схеме «Привязка mos.ru». При отказе от неё аккаунт сохраняется.
- Ошибка сервиса оставляет пользователя на текущей форме с введёнными данными. Реальные письма в прототипе не отправляются.

## AUTH1_MOS — Регистрация и вход через mos.ru

Цель: Войти по Mos ID или создать личный аккаунт при первом входе.

Запуск: Выбрать вход через mos.ru. Условия запуска: пользователь находится в соответствующем сценарии стенда; для подключения организации аккаунт уже создан, для привязки mos.ru — пользователь авторизован, для приглашения — открыта ссылка организации.

| ID | Участник | Действие / условие |
|---|---|---|
| start | Пользователь | Выбрать вход через mos.ru |
| provider | Пользователь / mos.ru | Ввести данные учётной записи mos.ru |
| consent | Пользователь | Разрешить передачу данных; для нового аккаунта принять условия |
| response | Платформа | Вход подтверждён и данные разрешены? |
| error | Платформа | Показать ошибку или отмену; аккаунт не менять |
| retry | Пользователь | Повторить вход? |
| cancel | Пользователь | Вход не выполнен |
| known | Платформа | Mos ID уже связан с аккаунтом? |
| existing | Платформа | Сохранить существующие организацию и роль |
| entered | Пользователь | Вход выполнен; сценарий завершён |
| new | Платформа | Создать аккаунт без локального пароля |
| registered | Пользователь | Аккаунт создан; предложить подключение организации |

Ветви: start → provider; provider → consent; consent → response; response → error (Нет); error → retry; retry → provider (Да); retry → cancel (Нет); response → known (Да); known → existing (Да); existing → entered; known → new (Нет); new → registered.

Результаты: Вход не выполнен; Вход выполнен; сценарий завершён; Аккаунт создан; предложить подключение организации.

- ФИО и email в предлагаемом варианте обязательны для передачи; телефон и сведения об организациях необязательны.
- Сведения об организации на mos.ru сами по себе не назначают права на ВЕРО. Это предлагаемый сценарий интеграции, не подтверждение фактического API.
- Пароль не генерируется и не показывается. Позже его можно задать в профиле. После успешного обычного входа кабинет на этом стенде не открывается.

## AUTH1_COMPANY — Подключение организации через УКЭП

Цель: Подключить организацию и получить подтверждённые полномочия генерального директора.

Запуск: Аккаунт создан; подключить организацию. Условия запуска: пользователь находится в соответствующем сценарии стенда; для подключения организации аккаунт уже создан, для привязки mos.ru — пользователь авторизован, для приглашения — открыта ссылка организации.

| ID | Участник | Действие / условие |
|---|---|---|
| start | Пользователь | Аккаунт создан; подключить организацию |
| select | Генеральный директор | Выбрать сертификат УКЭП |
| certificate | Платформа | Сертификат действующий и принадлежит гендиректору? |
| invalid | Платформа | Показать причину; доступ не предоставлять |
| review | Генеральный директор | Проверить сведения; дополнить контакты и недостающие поля |
| confirm | Генеральный директор | Подтвердить данные и контакты |
| send | Платформа | Принять данные на проверку |
| decision | Платформа | Проверка пройдена? |
| reject | Платформа | Сообщить причину отказа; права не выдавать |
| again | Генеральный директор | Выбрать другой сертификат? |
| no_access | Пользователь | Организация не подключена |
| approve | Платформа | Подключить организацию и сохранить роль руководителя |
| done | Пользователь | Организация подключена; регистрация завершена |

Ветви: start → select; select → certificate; certificate → review (Да); certificate → invalid (Нет); invalid → select (Другой сертификат); review → confirm; confirm → send; send → decision; decision → approve (Да); decision → reject (Нет); reject → again; again → select (Да); again → no_access (Нет); approve → done.

Результаты: Организация не подключена; Организация подключена; регистрация завершена.

- Контакты, КПП и сокращённое наименование можно дополнить до отправки. ИНН, ОГРН и сведения сертификата остаются только для чтения. Нет поиска по ИНН, приглашения команды и отдельной страницы ожидания.
- После отправки остаются данные и нейтральная кнопка «Отправлено». До положительного решения права руководителя не выдаются.
- ТЗ §6.2/LK-06 предусматривает проверку, но не устанавливает её длительность. В прототипе результат задаёт демонстрационная панель; реальные проверки не подключены.

## AUTH1_INVITE — Подключение сотрудника по приглашению

Цель: Получить только назначенный организацией доступ после принятия действующего приглашения.

Запуск: Открыть приглашение организации. Условия запуска: пользователь находится в соответствующем сценарии стенда; для подключения организации аккаунт уже создан, для привязки mos.ru — пользователь авторизован, для приглашения — открыта ссылка организации.

| ID | Участник | Действие / условие |
|---|---|---|
| start | Пользователь | Открыть приглашение организации |
| form | Платформа | Показать приглашение и неизменяемый email |
| account | Пользователь | Уже есть аккаунт? |
| new_password | Пользователь | Задать пароль, повторить и принять условия |
| login | Пользователь | Ввести пароль существующего аккаунта |
| merge | Пользователь | Продолжить выбранный путь |
| valid | Платформа | Данные входа / регистрации верны? |
| fix | Платформа / пользователь | Показать ошибку; исправить ввод |
| invitation | Платформа | Приглашение действует? |
| expired | Платформа / сотрудник | Сообщить об истечении / отзыве; обратиться к организации |
| denied | Пользователь | Без доступа к организации |
| accept | Платформа | Создать аккаунт при необходимости; принять приглашение |
| done | Пользователь | Вход выполнен с назначенными правами сотрудника |

Ветви: start → form; form → account; account → new_password (Нет); account → login (Да); new_password → merge; login → merge; merge → valid; valid → fix (Нет); fix → form (Исправить); valid → invitation (Да); invitation → expired (Нет); expired → denied; invitation → accept (Да); accept → done.

Результаты: Без доступа к организации; Вход выполнен с назначенными правами сотрудника.

- Логин — email, на который отправлено приглашение; в новой регистрации сотрудника поле заблокировано.
- Просроченное или отозванное приглашение не выдаёт доступ. Самостоятельного запроса доступа нет: сотрудник обращается к организации.
- Принятие приглашения не назначает административную роль и не создаёт МЧД. Дополнительные полномочия вне области этих схем.

## AUTH1_PASSWORD — Вход по email и восстановление пароля

Цель: Войти в существующий аккаунт; при необходимости восстановить пароль.

Запуск: Начать вход. Условия запуска: пользователь находится в соответствующем сценарии стенда; для подключения организации аккаунт уже создан, для привязки mos.ru — пользователь авторизован, для приглашения — открыта ссылка организации.

| ID | Участник | Действие / условие |
|---|---|---|
| start | Пользователь | Начать вход |
| login | Пользователь | Ввести email и пароль |
| valid | Платформа | Данные входа верны? |
| done | Пользователь | Вход выполнен; организация и роль сохранены |
| error | Платформа | Сообщить об ошибке входа |
| recover | Пользователь | Восстановить пароль? |
| email | Пользователь | Указать email аккаунта |
| mail | Платформа | Показать нейтральное сообщение об отправке письма |
| open | Пользователь | Открыть письмо и ссылку восстановления |
| link | Платформа | Ссылка действительна? |
| expired | Пользователь | Запросить новое письмо |
| password | Пользователь | Задать новый пароль и повторить |
| match | Платформа | Новый пароль корректен и совпадает? |
| fix | Пользователь | Исправить пароль; остальные данные сохранены |
| save | Платформа | Сохранить новый пароль; старый больше не подходит |

Ветви: start → login; login → valid; valid → done (Да); valid → error (Нет); error → recover; recover → login (Нет); recover → email (Да); email → mail; mail → open; open → link; link → expired (Нет); expired → email (Новое письмо); link → password (Да); password → match; match → fix (Нет); fix → password (Исправить); match → save (Да); save → login (Войти с новым паролем).

Результаты: Вход выполнен; организация и роль сохранены.

- При обычном входе организация уже подключена; новый поиск или повторная регистрация организации не предлагаются.
- После восстановления нет автоматического входа: пользователь возвращается к форме и вводит новый пароль.
- Неизвестный email получает такое же нейтральное сообщение, но не позволяет сменить пароль другого аккаунта. Ошибка сервиса сохраняет форму.

## AUTH1_LINK — Необязательная привязка mos.ru

Цель: Добавить вход через mos.ru к существующему аккаунту без создания дубля.

Запуск: Аккаунт уже создан. Условия запуска: пользователь находится в соответствующем сценарии стенда; для подключения организации аккаунт уже создан, для привязки mos.ru — пользователь авторизован, для приглашения — открыта ссылка организации.

| ID | Участник | Действие / условие |
|---|---|---|
| start | Пользователь | Аккаунт уже создан |
| choose | Пользователь | Выбрать «Подключить Mos ID» |
| provider | Пользователь / mos.ru | Войти в mos.ru |
| consent | Пользователь | Разрешить передачу данных |
| valid | Платформа | Авторизация подтверждена? |
| error | Платформа | Ошибка / отмена; аккаунт не изменён |
| retry | Пользователь | Повторить? |
| cancel | Пользователь | Привязка не выполнена |
| free | Платформа | Mos ID свободен для этого аккаунта? |
| conflict | Платформа | Сообщить о другой привязке; аккаунты не объединять |
| no_change | Пользователь | Существующий аккаунт сохранён |
| link | Платформа | Сохранить Mos ID в текущем аккаунте |
| done | Пользователь | Дополнительный способ входа подключён |

Ветви: start → choose; choose → provider; provider → consent; consent → valid; valid → error (Нет); error → retry; retry → provider (Да); retry → cancel (Нет); valid → free (Да); free → conflict (Нет); conflict → no_change; free → link (Да); link → done.

Результаты: Привязка не выполнена; Существующий аккаунт сохранён; Дополнительный способ входа подключён.

- Привязка не меняет существующий локальный пароль, организацию и назначенные права.
- При конфликте Mos ID другой аккаунт не объединяется с текущим. Можно отменить либо отдельно войти через mos.ru.
- Отвязка mos.ru в профиле допускается после задания локального пароля, чтобы сохранить способ входа.
