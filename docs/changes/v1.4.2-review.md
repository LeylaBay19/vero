Исходное поручение и объединённые комментарии переданы координатором. Применены ранее прочитанные правила независимого review и оценки тестов. Сравнительные варианты, новые схемы и реальная идентификация не входят в задачу.

## Проверка поведения

Код подтверждения удалён из сценария регистрации и mos.ru-приглашения. Успешная регистрация вызывает auth сразу; в обработчиках нет пути code/authPurpose/pendingPassword. Логин по паролю, проверки пароля/согласия и отмена mos.ru сохранены. Совпадение получателя приглашения имитируется исходными данными стенда, реальная проверка владения email не заявляется.

auth выбирает только из предоставленных fixture контекстов: ведомственный/организационный при наличии, иначе личный. Обязательного промежуточного выбора нет. После входа открывается home либо продолжается начатая услуга. Заголовочный селектор позволяет сменить уже назначенную организацию/работу от своего имени; он не предоставляет права и не создаёт новую связь.

Новые пункты меню работают как разделы кабинета. Команда формируется только для director, ведомственные данные — только для government. Обработчики повторно проверяют эти условия; существующие проверки render/submit команды сохранены. Ведомственный контекст не открывает клиентскую service-action. Смена контекста очищает историю, возвращает home и заново строит меню. Неавторизованному пользователю меню скрыто, действия sidebar/account-select не работают.

Приглашение до принятия оставляет личный контекст; «Не сейчас» ведёт в кабинет, где оно остаётся доступно. Принятие добавляет employee, без прав команды. Повторное принятие не добавляет ещё одну организацию. Сохранённая организация используется повторно по ИНН. Подготовка не выдаёт права, продолжение находится в разделе «Организация».

Отдельно не выдаются за дефект старые или искусственно заданные состояния, к которым не установлен пользовательский путь. Не заявляется промышленная защита по frontend-проверкам.

## Независимые выполненные проверки

Прочитаны актуальный исходник, переходы меню и обработчики. Реальные JS-обработчики исполнены в Node VM с заменой DOM, без замены логики:

- director после входа получает home с организацией; team доступна;
- переключение на personal возвращает home, team отклоняется;
- government получает home аналитики; data-access доступен, клиентский service-action отклоняется;
- после перехода government → personal data-access отклоняется;
- приглашённый до принятия имеет только личный контекст; отказ открывает home;
- последующее принятие открывает employee/home; повторный accept не создаёт дубль.

Все проверки passed. Отрицательные прямые вызовы обработчиков проверяют защитные условия; они не означают доказанную доступность скрытой кнопки в UI. Самостоятельное браузерное исполнение не выполнялось.
