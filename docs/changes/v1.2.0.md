# Исправления по браузерным комментариям · v1.2.0

Источник: четыре комментария пользователя к schemes.html от 04.11.2026. Границы: роли слева, ветка существующей организации, различие обычного входа и подписи МЧД, излом возвратной стрелки. Прежний снимок: локальный тег v1.1.0.

Схемы: роли вынесены в левую колонку всех SVG/PNG и согласованы с дорожками BPMN. В employee-invitation у возврата SignatureOK → Sign убраны соседние вертикальные сегменты с горизонтальным сдвигом 5 px. В organization-registration проверка существования дополнена проверкой сохранённого доступа; существующая организация не регистрируется повторно.

Прототип: подтверждённый аккаунт гендиректора открывает кабинет с сохранёнными правами при обычном входе по email/паролю или mos.ru. Если связь ещё не подтверждена, на странице существующей организации доступно подтверждение полномочий УКЭП и проверка платформой; до её успеха прав нет. Сотрудник без доступа обращается за приглашением. Подготовка МЧД не требует повторного входа через УКЭП, но подписание требует сертификата. Отдельный результат стенда «Нет УКЭП» блокирует подписание. Сохранённые подключения — тестовые серверные данные в демонстрационном переключателе, а не самостоятельный выбор роли в продукте. Актуальность связи и смена гендиректора требуют серверного проектирования; реальные интеграции отсутствуют.

Основание для подписания МЧД квалифицированной подписью доверителя: https://www.nalog.gov.ru/rn77/related_activities/el_doc/use_electronic_sign/. Поведение обычного повторного входа — проектное правило ВЕРО, не утверждение об интерфейсе Тринити.

Проверки: scripts/build_all.py; npm test (organization-access, unified-invitation, mchd, mos-org, sandbox, schemes); git diff --check. Пройдены новый доступ к существующей организации, отказ/повтор подтверждения, отсутствие дубля, сохранение роли при входе по паролю, подготовка МЧД без сертификата входа, запрет подписи без УКЭП, ограничения сотрудника, ранее существовавшие ветки приглашения и МЧД, sandbox и автономные схемы. PNG схем просмотрены. BPMN — описательные; запуск в конкретной BPMS не проверялся. Независимое ревью не выполнялось.

Версии интерфейса и схем фиксируются совместно. GitHub ожидает настройки входа Git пользователем; отправка не выполнена.
