# v1.8.0 — подключение, исправления, приглашения и роли

Coordination: ограниченная разработка standalone, база v1.7.1/f3d6207 с неизменённым тегом. Новые user-аннотации1–8 и добавления: сотрудники необязательным шагом подключения, кликабельная карточка компании в заявке. Ответы пользователя: срок «уточняется»; согласована форма текущих данных с предлагаемыми исправлениями, исходные сведения не меняются до проверки. МЧД исследуется как отдельный процесс, чекбокс выдачи в общем приглашении не добавляется. Исполнитель координатор; фактические модель/расход основного чата не предоставлены. Независимый review — отдельный /root/review_v2, scope запись только v1.8.0-review.md.

Изменение: заметный CTA подключения, блок исправлений, форма old/new по организации/ОГРН/адресу/ФИО; ИНН компании и владельца не редактируются. Correction snapshot прикладывается к заявке, исходная certificateData неизменна, принятые платформой предложения применяются только после approval. На действующей организации обращение готовится отдельно, автоматической перезаписи нет. Вопрос по заявке — отдельная форма с контекстом.

Подключение: данные/подтверждение → необязательное добавление сотрудников → отправить заявку/пропустить и отправить → ожидать решение. До одобрения не создаются ни директорский context, ни доступ сотрудников. Подготовленные строки только queued по конкретной компании; заявка содержит их снимок. После одобрения они становятся подготовленными приглашениями, не принятым членством. Реальной отправки нет. ИНН-проверка и обычный ввод не дают такую возможность; нужен пройденный certificate-review и явное подтверждение. Отказ/повтор проходят ту же границу.

Постоянные разделы «Приглашения» и «Мои организации» показывают отложенное решение и роли по компании/сервису. «Решить позже» не принимает приглашение; после принятия доступны назначенные сервисы, управление командой не появляется. Таблица сотрудников разделяет роль в организации и роли в сервисах, включая собственную строку руководителя. Во всех услугах сохранены пустые заглушки.

Заявка называется «Заявка на подключение организации». Native details карточки раскрывает исходные данные, предлагаемые исправления и список сотрудников. Срок «уточняется» по решению пользователя; есть поддержка. Это не обещание SLA или рабочей интеграции.
