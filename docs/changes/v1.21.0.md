# v1.21.0 — новые схемы варианта 1 и удаление лишнего блока

Поручения пользователя: убрать выделенный блок ожидания; проверить подход Тринити к редактированию; добавить схемы варианта 1; убрать «Начатая задача».

- В подключении организации удалено сообщение «Данные отправлены на проверку. До подтверждения права…». На том же экране после отправки остаётся нейтральная неактивная кнопка «Отправлено». Состояние проверки и запрет выдачи прав до одобрения сохраняются.
- Выбор «Начатая задача» скрыт в активном варианте 1; услуга не влияет на флоу регистрации/входа.
- На вкладке «Схемы» шесть новых схем исключительно текущего варианта 1. Исторические удалённые схемы не возвращались. Отдельно доступны email-регистрация, mos.ru, УКЭП организации, приглашение, email-вход/восстановление, необязательная привязка mos.ru.
- Один исходный набор моделей генерирует SVG, BPMN XML с DI-координатами, автономную HTML-страницу и ZIP. Источник scripts/auth_v1_diagrams.py; текущие модели/выгрузки processes-v1; карточки docs/business-processes-variant1.md.
- Пересечения подписей проверяются геометрически. В стрелках предусмотрены просветы под условиями и подписями событий; подписи развилок вынесены над ромбами. Масштабирование и прокрутка работают в защищённом iframe, политика sandbox/CSP не расширена.

## Проверка Тринити и рекомендация

Официальная инструкция ЛК заказчика, стр. 3: https://trinityeco.ru/api/trinity-auth-documents/assets/waste_generator_instruction_2026_06_29.pdf ; текстовый раздел «Шаг 1. Проверка сведений об организации» страницы https://trinityeco.ru/api/trinity-auth-documents/ . Просмотрены текст и иллюстрации локальной копии PDF. Подтверждено: после входа УКЭП первого лица сведения автоматически загружаются, пользователь их проверяет и дополняет недостающие, затем применяет изменения. Не подтверждено, какие именно загруженные поля можно перезаписывать; по изображению нельзя надёжно установить disabled/readonly.

Предложение для ВЕРО, а не утверждение о Тринити: ИНН, ОГРН, сведения владельца/срок сертификата оставить только для чтения; редактируемыми делать контакты и недостающие анкетные сведения. Пользователь задал вопрос, поэтому редактируемые поля не добавлялись автоматически. Прежний чат trinity_ossig_chat_history.txt не принят за первичное доказательство ограничений конкретных полей.

## Проверки и ограничения

Новый tests/variant1-schemes.cjs проверяет достижимость всех узлов/исходов, отсутствие наложения текстов, просветы у подписей, корректность XML/ссылок/DI, автономность, масштабирование и мобильную ширину. Проверен запрос скачивания из iframe: имя файла и содержимое Blob в родительской странице совпадают с BPMN-исходником. Сохранение файла браузер тестового окружения отменяет даже на отдельном TXT-примере; факт записи скачанного файла не подтверждён. Готовые BPMN/SVG и ZIP доступны как локальные артефакты независимо от браузера.

Схемы описывают предлагаемый процесс прототипа. Они не подтверждают реальные интеграции, проверку банка/подписи, сроки проверки или готовую серверную реализацию.
