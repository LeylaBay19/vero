## Результат проверки

Текущий код соответствует порученной смене UX: card больше не вставляет intro, форма входа содержит email/пароль, ненужные абзацы исчезли, регистрация вынесена отдельно. mos.ru сохранён. Не меняются роли и правила контекстов, приглашения, проверки компании и ведомственного просмотра.

Вход проверяет корректность email, непустой пароль и демонстрационное совпадение; успешный пароль сразу вызывает auth без кода. Регистрация проверяет пароль, подтверждение и согласие, затем требует код email; demoPassword изменяется только при правильном коде и authPurpose=register. После выхода введённый зарегистрированный пароль работает в текущем демонстрационном сеансе. Серверная учётная запись не заявлена; новый запуск стенда/перезагрузка сбрасывают демонстрацию.

Приглашённый пользователь ограничен почтой employee@example.test. В mos-ветке требуется отдельный код связывания получателя; authPurpose=invite-binding не создаёт новый пароль. Пустой/отменённый authPurpose не позволяет подтвердить старую форму кода. Граница успешной авторизации по-прежнему очищает историю и текущий контекст.

## Замечания и исправления

R1, P2 — первоначально регистрация принимала пароль из восьми пробелов (проверялся raw length), но последующий login отвергал его как пустой после trim. Это конкретное противоречие регистрации и входа. Автор добавил запрет all-whitespace и регрессию. На актуальной версии независимо проверено фактическим обработчиком submit: пробельная регистрация не авторизует и не начинает код. **Закрыто.** Первоначальная проблема установлена чтением исходного diff; независимый запуск до исправления не выполнен, так как автор уже сохранил исправление.

R2 — замечание об удобстве отмены mos.ru из регистрации: первоначально отмена возвращала login вместо register. Автор добавил mosOrigin. Независимый вызов реальных обработчиков register → mos → change-email теперь возвращает register, очищает authPurpose/pendingPassword. Это улучшение согласованности возврата, не установленный обход доступа. **Закрыто.**

## Выполненная независимая проверка

Прочитаны актуальный diff, полный затронутый JS и tests/platform-entry.cjs. В Node VM исполнялись реальные обработчики исходного HTML, заменялся только DOM. Успешно проверены:

- пробельный пароль отклоняется;
- регистрация с валидным паролем начинает подтверждение, неверный код не авторизует;
- верный код завершает регистрацию, после signout тот же пароль даёт вход;
- отмена mos.ru из регистрации возвращает правильный экран и сбрасывает отложенное подтверждение;
- отправка устаревшего code при authPurpose=null не авторизует.

Последний пункт — отдельная проверка защитного условия обработчика, а не заявление о доказанном пользовательском пути к устаревшей DOM-форме. Реальная смена формы удаляет её из страницы.

Автозаполнение заполняет только пустые поля, поддерживает пароль/подтверждение, не принимает согласие автоматически и не заменяет пользовательский ввод. Кнопки показа пароля имеют type=button; переключение не отправляет форму. Пароли сравниваются в исходном виде, поэтому намеренные пробелы вокруг непустого пароля не теряются при сравнении.
