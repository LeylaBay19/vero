# v1.22.0 — контакты и горизонтальный BPMN

Поручения: разрешить редактировать контакты/недостающие сведения; опубликовать схемы на сайте; добавить горизонтальный вариант в классическом BPMN-стиле; убрать отмеченную ссылку «ЛК · сводка».

До отправки изменяются контактные email, телефон, сайт и необязательные КПП/сокращённое наименование. Номера регистрации, сведения владельца и срок сертификата остаются только для чтения. Формат проверяется у поля без очистки других значений. Изменение контактов снимает прежнее подтверждение корректности; новое подтверждение делает пользователь. Сведения хранятся в черновике организации по ИНН, входят в снимок заявки; после отправки поля заблокированы. История возвращает введённые значения, автозаполнение их не перезаписывает.

Шесть процессов имеют две раскладки одной модели. Горизонтальная: монохромный пул, дорожки «Пользователь / руководитель» и «Платформа ВЕРО», события, задачи, XOR-шлюзы, ортогональные потоки, условия. Внешний mos.ru упоминается как контекст авторизации, а не моделируется как подтверждённая интеграция. SVG и BPMN экспортируются отдельно для обеих раскладок; BPMN содержит collaboration/participant, laneSet/flowNodeRef и DI-координаты. Скрипт scripts/auth_v1_horizontal.py меняет только представление, не добавляет новые ветви поведения. Вертикальные схемы сохранены.

Ссылка «ЛК · сводка» удалена из шапки. Основные разделы «Вход / Сравнение регистрации / Схемы» остаются. Выделенный блок ожидания не возвращался; после отправки есть только нейтральная кнопка «Отправлено».

Проверки: registration-contacts — форматы/неизменность идентификаторов/сохранение/история/подтверждение/мобильный экран; schemes — 12 SVG-видов без наложения текстов, переключатель/масштаб, 12 XML BPMN с DI, отсутствие сетевых запросов, правильное содержимое скачивания; onboarding-archive, stand-routing и prototype-history — затронутые переходы. Ограничение окружения скачиваний из v1.21.0 сохраняется; отдельный ZIP содержит все исходные BPMN/SVG.
