# v1.20.0 — пароль после mos.ru задаётся в профиле

По последней аннотации пользователя удалён блок «Данные для входа» после регистрации через mos.ru: нет автоматически созданного пароля, показа/копирования и предупреждения о единственном показе. Mos-аккаунт создаётся с `password: null`; обычный email/пароль не работает до явной установки пароля.

В справочном профиле: «Способы входа → Логин и пароль → Задать пароль». При первой установке старый пароль не запрашивается; новый вводится дважды и валидируется. После сохранения доступен вход по email и смена пароля с проверкой текущего. Отвязка mos.ru до установки пароля запрещена, чтобы не лишать пользователя единственного способа входа. Подключение/отмена mos.ru само по себе не назначает локальный пароль и не меняет пароль уже существующего аккаунта.

Активный вариант 1 стенда по предыдущему поручению заканчивается на входе/регистрации, без полного кабинета. Поэтому настройка профиля реализована в сохраняемом самостоятельном макете platform-entry-variant2.html; на регистрационном экране только короткое пояснение о настройке позже. Возвращать кабинет в путь регистрации не требуется.

Сохраняются все изменения v1.19.0: вход подключённого сотрудника/гендиректора без каталога, подключение организации с сертификата, отсутствие ручного поиска по ИНН, исправлений, приглашения команды и отдельной страницы ожидания. Ни реальных писем, ни интеграций, ни сертификатов нет.

Проверки: registration-mos-id обновлён под отсутствие генерации, настройку в профиле, повторный вход и защиту от отключения единственного способа; остальные затронутые UI-проверки и результат публикации фиксируются после выполнения.
