## Проверка реализации

- Единственный пункт «Организации» ведёт в my-organizations. Детали organization открываются из списка назначенных contexts, содержат явный возврат; вложенный экран подсвечивает родительский пункт. Отдельного дублирующего пункта organization нет.
- availablePowers требует доступную organizational связь для каждого документа. Сотруднику без отдельного права доступны только записи с recipientEmail текущего аккаунта. canIssuePower проверяет director либо employee с mayIssuePoa===true в соответствующей компании; строка role/name не используется как основание.
- Полученные/выданные/на подпись дополнительно разделяются по получателю, статусу и company capability. Директор одной компании не становится выдающим в другой компании, где он employee. Фильтр выбирает только назначенные компании и ограничивает выдачу, не меняя state.context или полномочия.
- power-open ищет ID только внутри availablePowers; modalHtml повторяет этот выбор. Детали не открываются по произвольному чужому ID. Все свободные текстовые реквизиты экранируются.
- authorized остаётся employee с отдельной подтверждённой fixture-capability и не получает team/finance. Отображение документов не содержит действий выпуска/подписи/отзыва с фиктивным успехом.
- seedPowers вызывается при начальном auth над заранее заданными contexts. Обычный invite/new начинается без документов; accept и approve не вызывают seed и не добавляют powers. Реестр не создаёт МЧД из членства, очереди сотрудников или новой компании. Три услуги остаются пустыми заглушками.

## Независимые проверки

В Node VM исполнены реальные функции/обработчики текущего HTML, заменён только DOM. Passed:

1. Employee получает только собственную запись; добавленная в тестовую память чужая запись той же компании исключается, её ID не открывает modal.
2. Название роли «Руководитель» у employee не даёт canIssuePower; произвольный kind=admin даже с флагом не принимается. Явная employee-capability принимается.
3. В multi чужая запись Вектора недоступна, хотя пользователь director в ООО «Пример»; filter Вектора не меняет текущий контекст.
4. Authorized открывает доступную выданную запись, но в меню отсутствуют team и finance.
5. Обычное принятие приглашения оставляет powers пустым.

Вставка отрицательной записи выполнялась лишь в изолированной памяти VM для проверки guard, не в файле/приложении пользователя. Прямые отрицательные вызовы не означают видимости скрытой кнопки в интерфейсе.
