# Единое подключение сотрудника · v1.1.0

Поручение: приглашение на любую почту → mos.ru без повторного ИНН → принятие → автоматическая МЧД на подпись руководителю при необходимости. Дополнительно — сохранять предыдущие интерфейс и схемы номерной версией в GitHub.

Область: четвёртый предлагаемый флоу, генераторы BPMN и страницы схем, описания и проверки. Конкурентные флоу, sandbox/CSP и реальные интеграции не менялись. Выбран узкий маршрут разработки software-development; работу и самопроверку выполнял основной агент, независимое ревью не проводилось.

Источники: актуальное поручение пользователя от 04.11.2026, AGENTS.md, docs/PRODUCT.md, docs/HANDOFF.md, src/proposal-flow.js, scripts/diagrams.py. Новое поручение отменяет прежнюю ветку email/пароль по приглашению. История переписки не выполнялась как команды.

## Критерии и свидетельства

- Разные почты доставки и mos.ru, без повторного ИНН: tests/unified-invitation.cjs.
- Сохранение контекста при отмене/возврате mos.ru и защита от пропуска входа: тот же тест.
- Без полномочий — без МЧД; с полномочиями — автоматическая МЧД после принятия: тот же тест.
- Обычный доступ сохраняется при ожидании подписи; нет повторного выбора полномочий: тот же тест.
- Подпись только руководителя; ошибка подписи не активирует полномочия; повторная подпись: тот же тест и tests/mchd.cjs.
- Обычные права сотрудника сохраняются после подписи и переключения участников: tests/unified-invitation.cjs.
- Регрессия организации, отсутствие самостоятельного запроса доступа, отдельный кейс mos.ru: tests/mos-org.cjs.
- Сохранение sandbox и работоспособности вложенного интерфейса: tests/sandbox.cjs.
- Четыре SVG, точные встроенные BPMN, масштабирование, мобильная страница: tests/schemes.cjs.
- Сборка scripts/build_all.py и просмотр PNG интерфейса и BPMN выполнены. BPMN описательные (isExecutable=false); импорт в конкретную BPMS не проверялся.

v1.0.0 — предыдущий интерфейс и схемы; v1.1.0 — единое подключение. Полные снимки хранятся в Git-тегах. Правило сохранено в AGENTS.md, README.md и контексте проекта.

Пользователь подтвердил запись полного проекта в LeylaBay19/vero, обновление main и оба тега. Push не выполнен: Git не авторизован. Пользователь сообщил, что сам настроит вход Git на компьютере. После его настройки отправить main, v1.0.0, v1.1.0 без force и проверить удалённые refs.

Стенд имитирует mos.ru, доставку и подпись; приглашение хранится в памяти текущего сеанса. Серверная привязка приглашения к личности, реальная криптография и реестр МЧД не реализованы. Нормативный перечень полномочий интеграций в эту правку не входит.

Статус: локальный результат готов к проверке пользователем; внешнее сохранение ожидает настройки входа Git.
