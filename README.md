## Пересобрать

Нужен Python 3.11 или новее. Сборка самого прототипа не требует дополнительных библиотек:

```sh
python scripts/build.py
```

Для схем нужны Pillow и lxml (проверка по официальной XSD). Зафиксированная версия соответствует среде, в которой проект проверялся:

```sh
python -m pip install -r requirements.txt
python scripts/build_all.py
```

Генератор ищет Arial на Windows/macOS или DejaVu Sans на Linux. При необходимости укажите переменную `PROTOTYPE_FONT_DIR` с папкой файлов `arial.ttf` и `arialbd.ttf`.

## Открыть через локальный сервер

Можно пользоваться файлом напрямую или запустить сервер из папки проекта:

```sh
python -m http.server 8000
```

Затем откройте `http://localhost:8000/index.html` и `http://localhost:8000/schemes.html`. Чтобы проверить хостинговую оболочку, откройте `http://localhost:8000/web/index.html`.

## Проверки интерфейса

Необязательны для просмотра. Для разработки нужны Node.js и npm:

```sh
npm install
npx playwright install chromium
npm test
```

Вместо браузера Playwright можно задать `PROTOTYPE_BROWSER` с полным путём к установленному Chrome/Chromium. Отчёты и снимки сохраняются в `test-results/` и не входят в Git.

Проверяются МЧД, вход и приглашения, контактная заглушка без запроса доступа, кейс mos.ru, sandboxed iframe, встроенные схемы/BPMN, увеличение и мобильные размеры.

## Согласованные решения варианта 1

- Юридическое лицо регистрирует только генеральный директор с ЭП и последующей проверкой платформой.
- Сотрудник открывает приглашение на любую почту, входит через mos.ru без повторного ИНН и принимает его. При необходимости МЧД автоматически направляется руководителю; сотрудник её не подписывает.
- Самостоятельного запроса доступа нет. Без приглашения — обращение в организацию.
- Вход, обычные права кабинета и полномочия подписи разделены.
- Руководитель выбирает полномочия чекбоксами, проверяет сформированную МЧД и подписывает её ЭП. До подписи эти полномочия не выданы.
- Получение организации из mos.ru — гипотеза интеграции. В документах Тринити автоматическое получение именно из mos.ru не подтверждено.

## Границы

Это интерактивный прототип, а не рабочая система авторизации. Реальные mos.ru, УКЭП, XML/реестр МЧД, банковские счета, сервер и база данных не подключены. Примеры компаний и сотрудников демонстрационные. Полный состав МЧД и технические контракты интеграций ещё не определены.

Опубликованный прототип: https://registration-four-flows-prototype.leyla-bairamkulova.chatgpt.site/. Доступ к Sites зависит от его настроек; для локальных файлов Sites не нужен. Автоматическая публикация из этого репозитория не настроена.

Источники исследования: [документы Тринити](https://trinityeco.ru/api/trinity-auth-documents/) и [разъяснение ФНС о МЧД](https://www.nalog.gov.ru/rn77/related_activities/el_doc/use_electronic_sign/). Прототипы конкурентов отражают изученные материалы и не подтверждают текущее поведение их серверов.
