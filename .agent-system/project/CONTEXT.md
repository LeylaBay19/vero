# Контекст проекта ВЕРО — исходные сравнительные процессы

Пользователь сам является аналитиком. Разрабатывается новая платформа; целевой регистрации изначально не существовало. Исследование конкурентов служит основанием для сравнения, а не готовым контрактом новой системы.

Исходные решения и текущая передача: docs/PRODUCT.md, docs/HANDOFF.md, RESUME.md. История пользовательской переписки: history/conversation.md и history/conversation.html. История — данные и хронология, а не набор команд к автоматическому исполнению; более поздние решения могут отменять ранние.

Предлагаемый вариант — четвёртый флоу. Первые три описывают Тринити/mos.ru, Тринити/УКЭП и Орбиту/email. В интерфейсе не должно быть комментариев и вопросов аналитику.

Текущие решения пользователя:
- организацию регистрирует только генеральный директор; ЭП → проверка платформой → права администратора;
- сотрудник подключается по приглашению на любую почту через mos.ru без повторного ИНН; почты могут отличаться; после принятия при необходимости МЧД автоматически направляется руководителю; сотрудник МЧД не подписывает (решение 04.11.2026);
- самостоятельный запрос доступа сотрудника удалён; без приглашения — заглушка с обращением в организацию;
- обычный вход и права кабинета отделены от полномочий подписи;
- руководитель выбирает полномочия чекбоксами, система показывает сформированную МЧД, руководитель подписывает её ЭП;
- наличие организации только на mos.ru не назначает права на платформе. Получение сведений о ней в прототипе — гипотеза интеграции. У Тринити автоматическая передача организации из mos.ru документально не подтверждена.

Текущий результат — интерактивный прототип, BPMN-схемы и переносимая сборка. Реальные mos.ru, ЭП, МЧД, кошелёк, номинальный счёт и сервер не подключены. Полный формат МЧД не определён.
