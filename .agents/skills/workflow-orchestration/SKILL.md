# Оркестрация выбранного пакета

1. Прочитай `.agent-system/active.json`, общие контракты, контекст проекта и выбранные `pack.json`/`WORKFLOW.md`. Выбери пакет по задаче, используя default_pack только при отсутствии более точного поручения.
2. Зафиксируй в coordination.md цель, критерии, входные версии, выбранные этапы, исполнителей и отдельные области записи. Не запускай работу над продуктом по запросу лишь настроить библиотеку.
3. Определи необходимые входы текущего этапа. Назначь исполнителю роль, её профиль, процедуры, точные источники и выходной контракт из пакета. Пакеты могут расширять набор скиллов роли через role_skills; роль не обязана знать все возможные пакеты.
4. Проверяй содержание, версии, доказательства и ограничения пакета передачи. Наличие файлов не доказывает готовность. Обязательный пробел или решение человека блокирует зависимую ветку; независимую порученную работу продолжай.
5. Параллельно запускай только независимые части с разными выходами. Общие ID и итоговый артефакт сводит один назначенный исполнитель. Review должен быть независим от автора, если это предусмотрено маршрутом.
6. Возвращай дефекты ответственной роли, недостаток фактов на целевой анализ, вопросы смысла человеку. После исправления обновляй зависимые проверки и свидетельства. При повторе без новых данных показывай конкретный блокер вместо бесконечной переписки.
7. При отсутствии нужного модуля или инструмента сообщи ограничение, не имитируя работу. Если профиль нельзя выбрать по имени, передай его инструкции субагенту явно. Файл профиля сам по себе не является доказательством отдельного запуска.
8. Заверши последним порученным этапом. Проверь исходные критерии, покажи результаты и вопросы. Готовность к приёмке не равна приёмке человеком или разрешению на публикацию.

Выход — актуальный coordination.md, ссылки на результаты этапов, версии, ограничения и следующий допустимый шаг. Порядок предметных этапов и обязательные артефакты находятся в пакете, а не дублируются в этом скилле.
