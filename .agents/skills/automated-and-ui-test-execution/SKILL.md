# Выполнение проверок

Перед выполнением установи версию, среду, тестовые данные, ожидаемые результаты и границы разрешённых действий. План проверки или наличие инструмента не является разрешением воздействовать на production или внешние данные.

- Запускай подходящие проверки проекта, начиная с относящихся к изменению; расширяй набор по рискам и новым результатам. Записывай точную команду, рабочий каталог, условия, время/версию и исход.
- UI проверяй, если он релевантен и доступен: роль, начальные условия, шаги, наблюдаемый результат, разрешённые снимки или другие свидетельства. Скриншот подтверждает только наблюдаемое на нём; он не заменяет проверку серверного результата.
- Изолируй тестовые данные в назначенной среде. Не выполняй реальные платежи, рассылки, удаление данных, миграции или внешние действия без соответствующего поручения. При отсутствии доступа/разрешения отметь блокер и продолжи независимые проверки.
- Различай сбой проверяемого поведения, ошибку тестового стенда, отсутствие зависимости и неопределённость требования. Ошибка инфраструктуры не означает автоматически дефект продукта или успешную проверку.
- Не исправляй продуктовый код и не ослабляй тест под ожидаемый успех. При порученном добавлении теста сохраняй исходное требование. После исправления версии перепроверь затронутые проверки и обоснованную регрессию.

Веди `test-evidence.md`: ID проверки, версия результата, среда/условия, действие, ожидаемый и фактический результат, исход, ссылка на лог/снимок, ограничения. Не сохраняй секреты или лишние персональные данные. Сохраняй фактические неуспехи; не заменяй их итогом другого запуска без истории.
