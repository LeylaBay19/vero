# Связи требований и UX

Используй ID, определения и правила свидетельств общей [методологии](../product-documentation-methodology/SKILL.md) и её релевантных references в `.agents/skills`. Входы: версии требований и сценариев, извлечённые UX-наблюдения и их первичные локаторы.

1. Для каждого требования или сценария, затрагивающего UX, укажи соответствующие экраны, состояния, действия и переходы. Для требования без видимой UX-части обозначь неприменимость с причиной; не требуй экран для каждого NFR или серверного правила.
2. Построй проверяемую связь `source → requirement → scenario → UX/diagram`. Сохраняй прямые первичные свидетельства у UX, если требование ещё не установлено. Пропуск звена — явный пробел, а не повод создать новое требование.
3. Охарактеризуй связь: подтверждает видимое представление, частично отражает, расходится, не найдено в просмотренной области, неизвестно или неприменимо. Объясни, что именно покрыто и чем; наличие ссылки без такого основания недостаточно.
4. Проверь связи в обе стороны. Требование без UX-основания и экран без установленного сценария являются разными вопросами. Непривязанный экран может быть наблюдаемым фактом; он не превращается в утверждённую потребность продукта.
5. Для расхождения сохрани формулировки обеих сторон, версии и локаторы, влияние на сценарий и вопрос владельцу решения. Не разрешай конфликт по новизне файла, должности автора или внешней убедительности макета.

Выход — назначенный `ux-traceability.md` либо заданный раздел общего реестра. Минимальная запись: ID требования/сценария; ID UX/схемы; source ID и локатор; характер и граница связи; версия; пробел/вопрос. Исследовательские записи с тем же ID сохраняют происхождение определения, авторитетное изложение которого находится в PRODUCT.md.

Проверь, что связи не подменяют друг друга: макет не доказывает выполнение FR/NFR, прототип — серверный эффект, а отсутствие фрейма — отсутствие функции. Передай Автору проверенные связи и пробелы для читательского комплекта; независимая проверка и приёмка остаются отдельными действиями.
