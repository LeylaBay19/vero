# Проверка рабочего состояния

## Вход
Корень исследуемого проекта, область анализа, разрешённый каталог результатов и планируемые действия. Если путь записи не назначен, чтение можно продолжить; до записи выбери свободный каталог внутри разрешённой рабочей области.

## Действия
1. Прочитай применимые инструкции проекта. Проверь существование исходников и целевых файлов, права доступа и условия, способные повлиять на работу.
2. Если это Git-репозиторий, используй операции чтения: `git status --short --branch`, при необходимости ограниченные `git diff --stat` и `git diff -- <путь>`. Предпочитай `git --no-optional-locks` для обследования. Не выводи содержимое секретов. Не запускай `reset`, `clean`, `checkout`, `stash`, `add`, `commit` и исправления рабочего дерева ради подготовки анализа.
3. Отдели чужие изменения от назначенных выходов настолько, насколько позволяют факты. Сам факт изменённого файла не доказывает его автора. Если владение неизвестно, так и укажи.
4. Для каталога без Git явно запиши, что версия и владение изменениями через Git не установлены. Используй доступные метаданные; не создавай репозиторий.
5. При коллизии имени выбери новый выходной файл или запроси необходимое решение. Не перезаписывай пользовательскую правку. Незавершённые изменения, не затронутые чтением и назначенной записью, сами по себе не блокируют анализ.

## Выход
`working-copy-safety.md` в назначенном каталоге: проверенные пути, исходное состояние, известные изменения/ограничения, разрешённые выходы, конкретные конфликты и статус `ready`, `ready-with-limitations` или `blocked`. Статус относится к возможности выполнить порученную работу, а не к безопасности продукта в целом.

## Завершение
Понятно, что можно читать и куда безопасно записывать результат. Блокируй только действия с реальным конфликтом или недостающим доступом. Не заявляй, что файлы не изменились за весь анализ, если повторной проверки не было.
